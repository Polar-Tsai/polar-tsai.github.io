## 用餐流程與情境描述

這天我到大型連鎖餐廳吃飯。

外場人員會先透過座位管理系統確定空位後，設定人數、列印小白單（桌號單），然後帶我入座並指示我掃描 QR Code 點餐。

選定適合今天的我大吃的餐點後，等待片刻後餐點陸續送上，用餐完畢後我再自行前往櫃台排隊結帳。

## 痛點觀察

以一位熟稔 3C 用品的客人來說，整體流程簡單，但仍存在顯著的瓶頸 — **尖峰用餐時段的結帳櫃台往往大排長龍**。

在餐飲業人力資源極為短缺情況下，一位外場往往身兼數職，需要帶位、收銀，有時候甚至得協助走餐、收桌。此時已用完餐只需結帳完即可離開的客人，卻必須卡在人龍等待結帳，體驗不佳。

## 現行方案的優點分析

從原本紙本點餐、平板點餐，現已轉變為利用 QR Code 由客人驅動點餐觸發點且無須外場手動填入點餐資料。這是一個由使用者主動觸發的設計，一來是讓顧客成為**流程的參與者，增加主動性**、提升顧客在流程上的控制節點；二來則是**減輕**餐廳外場人員的**作業壓力**。

## 若能整合結帳功能

🧑🏿 以客人而言 → **UX 視角**

1. 使用者自主性提高：可以於完餐後任何時機點結帳，無需等待他人操作，掌握時間掌控感
2. 減少社交壓力：提供內向人完美的用餐體驗（這是我最愛的）
3. 流程閉環：一支手機點餐 → 結帳 → 用餐 → 用餐完畢 → 高歌離席，在此服務流程下形成完整的服務旅程

💁🏿 以外場人員而言 → **第一線營運**

1. 提升餐點品質：心力更專注於第一時間提供客人甫完成的餐點
2. 收桌人員更充沛 → 提高翻桌率
3. 無須點滿收銀技能：關帳時的帳目比對錯誤率更低，大家可以準時下班

🏦 以公司來說 → **潛在商業效益**

1. 減少培訓成本、降低流動率：第一線外場人員流動率或可降低，減少一個需要專注度的工作項目，可以留住對於算帳、數字有恐懼但有高度服務力的人才（身為曾在餐飲業打工，卻打死都不敢碰收銀的我 Be like）
2. 減少門市的帳務落差：無須花額外人力處理各門市前一晚結帳錯誤所產生的處理成本
3. 減少客訴：這也與第 1、2 點有連貫，因為收銀這項任務需要縝密以及高臨機應變能力，小失誤可能是找零有誤，當場處理即可；大至信用卡結帳但選錯成現金結帳，導致帳目比對有誤，接連一連串要與客人聯絡追款而導致不滿等等，而這些都是與收銀技能點需要點到熟練程度才能避免；而若人員不熟稔整個收銀流程，可能在尖峰餐期需要額外拉一個人力協助，此時更會犧牲服務品質。

## 那麼，是什麼原因總公司選擇不結合點餐 + 結帳功能整合呢？

1. **POS 系統與外部點餐系統未整合**：現場使用的 POS 系統（收銀與點餐系統）架構可能較為封閉，較無擴展性，因此無法與外部點餐服務（QR Code 點餐平台）完成資料串接。導入時間可能需要花費大量開發成本與資訊人員等工時成本
2. **金流串接成本高**：有些金融系統也相對封閉，總公司也許為了避免與錢相關的系統需要在承擔風險之下進行金流整合。
3. **更看重結帳時的人的溫度**：由於該品牌講求的是服務溫度，因此在收銀節點上，更希望能在最後一個服務步驟，由第一線人員親口詢問餐點滿意與否，會更能讓客人感受到溫度
4. **與商場方的帳務同步**：以收銀結帳系統為例，一間在商場開店的餐飲，原先需要將資料拋送到餐飲總公司，計算營收、當天結算數量以外，也需要將資料也同步到商場的收銀結帳系統。簡單粗暴的說明，即一筆客人的結帳明細，會同時出現在商場方和總公司。

身為一位正在學習 UX 的人，我學習到：

1. 使用者痛點觀察不能只注重表面，應考慮到整理服務流程
2. 有效設計不應該只是考慮流程上的單一節點，應通盤考慮到整體流程，以免只是把便利建立在別人的痛苦上
3. UX 往往也因不同環境、資源充沛與否、技術限制有關，並非單純的畫面美觀就是好的 UX
4. 除了總公司的收銀系統整合，也要考量整合商場方的收銀系統所需成本。
